---
title: Event Bus
description: Emulate EventBridge, Event Grid, and Eventarc — route events through buses, rules, and targets entirely in memory.
---

Route events between services without any real infrastructure. cloudemu emulates the **event-routing control plane** of all three clouds — creating event buses, defining rules that filter events by pattern, attaching targets, and publishing events that get matched and delivered. Every call runs against local in-memory state, so your code can publish an event and immediately assert on what the rules matched, with nothing to provision or tear down.

| Provider | Real service | cloudemu driver |
|---|---|---|
| **AWS** | EventBridge — buses, rules, targets | `aws.EventBridge` |
| **Azure** | Event Grid — topics and subscriptions | `azure.EventGrid` |
| **GCP** | Eventarc — event routing | `gcp.Eventarc` |

There are two ways to drive it, both backed by the same in-memory state:

- **Real cloud SDK** — point your existing `aws-sdk-go-v2`, `armeventgrid`, or Eventarc REST client at a local server. Only the endpoint changes; your real code is untouched — the same client works in a test, a local dev server, or your running app.
- **Portable Go API** — call cloudemu's Go interface directly from your application code — discover resources, perform actions, skip the HTTP hop entirely. The same method shape works across every cloud, so you can switch providers by changing one field.

## Drive it with the real SDK

cloudemu ships an HTTP server per cloud that speaks that provider's real wire protocol. Run it with `httptest` in a test or behind a real `http.Server` in your app, hand it the drivers you need, and point your normal SDK client at its URL — nothing else in your code changes.

<Tabs items={['AWS', 'Azure', 'GCP']}>

<Tab value="AWS">

```go
import (
    "github.com/aws/aws-sdk-go-v2/aws"
    awseb "github.com/aws/aws-sdk-go-v2/service/eventbridge"
    ebtypes "github.com/aws/aws-sdk-go-v2/service/eventbridge/types"
    awsserver "github.com/stackshy/cloudemu/v2/server/aws"
)

cloud := cloudemu.NewAWS()
ts := httptest.NewServer(awsserver.New(awsserver.Drivers{EventBridge: cloud.EventBridge}))

client := awseb.NewFromConfig(cfg, func(o *awseb.Options) {
    o.BaseEndpoint = aws.String(ts.URL) // the only change from real AWS
})

client.CreateEventBus(ctx, &awseb.CreateEventBusInput{Name: aws.String("orders-bus")})
client.PutRule(ctx, &awseb.PutRuleInput{
    Name:         aws.String("order-created"),
    EventBusName: aws.String("orders-bus"),
    EventPattern: aws.String(`{"source":["orders"]}`),
    State:        ebtypes.RuleStateEnabled,
})
```

## Drive it with the Portable Go API

Call cloudemu's Go interface directly and skip the HTTP hop. The method shape is identical across every cloud, so switching providers is a one-field change — the buses, rules, targets, and publishing all behave the same way underneath.

<Tabs items={['AWS', 'Azure', 'GCP']}>

<Tab value="AWS">

```go
import ebdriver "github.com/stackshy/cloudemu/v2/services/eventbus/driver"

bus, _ := aws.EventBridge.CreateEventBus(ctx, ebdriver.EventBusConfig{
    Name: "app-events",
})

aws.EventBridge.PutRule(ctx, &ebdriver.RuleConfig{
    Name:         "order-rule",
    EventBus:     bus.Name,
    EventPattern: `{"source": ["orders"]}`,
})
aws.EventBridge.PutTargets(ctx, bus.Name, "order-rule", []ebdriver.Target{
    {ID: "process-order", ARN: "arn:aws:sqs:::orders-queue"},
})

aws.EventBridge.PutEvents(ctx, []ebdriver.Event{{
    Source:     "orders",
    DetailType: "OrderCreated",
    Detail:     `{"orderId": "123"}`,
    EventBus:   bus.Name,
}})
```

</Tab>

## What each provider supports

All three providers implement the same event-routing interface — cloudemu maps each cloud's real service onto a shared set of operations.

<Tabs items={['AWS', 'Azure', 'GCP']}>

<Tab value="AWS">

**EventBridge** — full bus lifecycle with `CreateEventBus`, `GetEventBus`, `UpdateEventBus`, `ListEventBuses`, and `DeleteEventBus`. Rules are managed with `PutRule`, `GetRule`, `ListRules`, `DeleteRule`, and can be toggled via `EnableRule` / `DisableRule`. Targets attach through `PutTargets`, `ListTargets`, and `RemoveTargets`. Publish with `PutEvents`, and replay with `GetEventHistory`.

</Tab>

<Tab value="Azure">

**Event Grid** — the same interface, scoped to an Azure subscription and resource group. Create and manage topics as event buses, define subscriptions as pattern-filtered rules (`PutRule` / `EnableRule` / `DisableRule`), attach targets, and publish with `PutEvents`. `ListEventBuses` honors the subscription/resource-group scope.

</Tab>

<Tab value="GCP">

**Eventarc** — the same operations, scoped to a GCP project. Buses, rules, and targets all use the shared methods, and `PutEvents` matches published events against your rules exactly as the AWS and Azure backends do.

</Tab>

</Tabs>

## How the emulator behaves

cloudemu doesn't just store buses and rules — it reproduces the routing behavior of the real service, so your code exercises real matching logic:

- **Events are matched against patterns.** `PutEvents` evaluates each event against every rule's `EventPattern` and routes only the matches. An empty pattern matches everything; a `{"source": [...]}` pattern filters by source, just like real EventBridge.
- **Matched deliveries emit metrics.** Each publish records how many events were matched into the monitoring service, so your code can assert how many events a rule actually caught.
- **History is replayable.** `GetEventHistory` returns recently published events for a bus, letting tests inspect or replay what was emitted.
