title: DNS
description: Emulate Route 53, Azure DNS, and Cloud DNS — zones, records, weighted routing, and health checks, all in memory.

Model DNS entirely in memory. cloudemu implements the **DNS control plane** of all three clouds — creating hosted zones, adding and listing records, weighting records for traffic distribution, and running health checks against endpoints. Nothing resolves against the real internet and no zone is ever registered, so you can test the DNS configuration your app depends on — service discovery, failover routing, record management — without a real account or a live domain.

| Provider | Real service | cloudemu driver |
|---|---|---|
| **AWS** | Route 53 | `aws.Route53` |
| **Azure** | Azure DNS | `azure.DNS` |
| **GCP** | Cloud DNS | `gcp.CloudDNS` |

There are two ways to drive it, both backed by the same in-memory state:

- **Real cloud SDK** — point your existing `aws-sdk-go-v2`, `azure-sdk-for-go`, or `google.golang.org/api` client at a local server. Only the endpoint changes; your real code is untouched — the same client works in a test, a local dev server, or your running app.
- **Portable Go API** — call cloudemu's Go interface directly from your application code — discover resources, perform actions, skip the HTTP hop entirely. The same method shape works across every cloud, so you can switch providers by changing one field.

## Drive it with the real SDK

cloudemu ships an HTTP server per cloud that speaks that provider's real wire protocol. Run it with `httptest` in a test or behind a real `http.Server` in your app, hand it the drivers you need, and point your normal SDK client at its URL — nothing else in your code changes.

<Tabs items={['AWS', 'Azure', 'GCP']}>

<Tab value="AWS">

```go
import (
    "github.com/aws/aws-sdk-go-v2/aws"
    awsr53 "github.com/aws/aws-sdk-go-v2/service/route53"
    r53types "github.com/aws/aws-sdk-go-v2/service/route53/types"
    awsserver "github.com/stackshy/cloudemu/server/aws"
)

cloud := cloudemu.NewAWS()
ts := httptest.NewServer(awsserver.New(awsserver.Drivers{Route53: cloud.Route53}))

client := awsr53.NewFromConfig(cfg, func(o *awsr53.Options) {
    o.BaseEndpoint = aws.String(ts.URL) // the only change from real AWS
})

created, _ := client.CreateHostedZone(ctx, &awsr53.CreateHostedZoneInput{
    Name:            aws.String("example.com."),
    CallerReference: aws.String("ref-1"),
    HostedZoneConfig: &r53types.HostedZoneConfig{
        Comment:     aws.String("test zone"),
        PrivateZone: false,
    },
})
```

</Tab>

```go
import (
    "github.com/Azure/azure-sdk-for-go/sdk/azcore/to"
    "github.com/Azure/azure-sdk-for-go/sdk/resourcemanager/dns/armdns"
    azureserver "github.com/stackshy/cloudemu/server/azure"
)

cloud := cloudemu.NewAzure()
ts := httptest.NewTLSServer(azureserver.New(azureserver.Drivers{DNS: cloud.DNS}))

// Point the real armdns client factory at ts (endpoint + ts.Client()).
cf, _ := armdns.NewClientFactory("sub-1", cred, optsFor(ts))
zones := cf.NewZonesClient()

created, _ := zones.CreateOrUpdate(ctx, "rg-1", "example.com", armdns.Zone{
    Location: to.Ptr("global"),
    Tags:     map[string]*string{"env": to.Ptr("test")},
}, nil)
```

```go
import (

    DnsName: "example.com.",
}).Context(ctx).Do()
```

## What each provider supports

Every provider implements the same DNS driver, so the surface is uniform — only the resource naming differs to match each cloud.

<Tabs items={['AWS', 'Azure', 'GCP']}>

<Tab value="AWS">

**Route 53 hosted zones** — `CreateZone`, `GetZone`, `ListZones`, `UpdateZone`, and `DeleteZone`, public or private. Full record management with `CreateRecord`, `GetRecord`, `ListRecords`, `UpdateRecord`, and `DeleteRecord` across `A`, `AAAA`, `CNAME`, `MX`, `TXT`, `NS`, `SOA`, and `SRV` types. Records can carry a **weight** for weighted routing, and you can attach **health checks** (`CreateHealthCheck` and friends) to endpoints.

</Tab>

<Tab value="Azure">

**Azure DNS zones** — the same CRUD for zones and records as the other clouds, with zones scoped to a subscription and resource group so scoped `ListZones` calls filter to the right container. Records support the full type set, weighted routing via per-record weights, and health checks against endpoints.

</Tab>

<Tab value="GCP">

**Cloud DNS managed zones** — zones and records with matching `Create` / `Get` / `List` / `Update` / `Delete` semantics, scoped to a project. Records span the same type set, support weights for weighted routing, and pair with health checks for endpoint monitoring.

</Tab>

</Tabs>

## How the emulator behaves

cloudemu reproduces the routing and resolution behavior of real DNS, not just a record store:

- **Weighted routing.** Records carry a `Weight`, so you can model traffic split across multiple endpoints and test how your app picks a target under weighted distribution.
- **Health checks are stateful.** Create a health check against an endpoint, then flip its status between `HEALTHY` and `UNHEALTHY` with `SetHealthCheckStatus` to exercise failover paths deterministically.
- **Zones resolve.** The `topology` engine reads DNS zones directly, so `Resolve` walks your zones and records to turn a hostname into its values — the same lookup a real resolver would perform.

## Or call the Portable Go API directly

The examples above already use the Portable Go API — the same in-process interface across all three clouds. Switching providers is a one-line change: swap the driver field and every call stays the same.

<Tabs items={['AWS', 'Azure', 'GCP']}>

<Tab value="AWS">

```go
zone, _ := aws.Route53.CreateZone(ctx, dnsdriver.ZoneConfig{Name: "example.com"})
zones, _ := aws.Route53.ListZones(ctx, scope.Scope{})
```

</Tab>

<Tab value="Azure">

```go
zone, _ := azure.DNS.CreateZone(ctx, dnsdriver.ZoneConfig{Name: "example.com"})

```

</Tab>
