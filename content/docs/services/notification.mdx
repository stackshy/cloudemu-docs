title: Notification
description: Emulate SNS, Azure Notification Hubs, and FCM — topics, subscriptions, and message fan-out in memory.

Model pub/sub notifications entirely in memory. cloudemu implements the **topic-and-subscription** shape of all three clouds — creating topics, subscribing endpoints to them, and publishing messages that fan out to every subscriber. No SNS topic is ever created, nothing is billed, and every call returns in milliseconds, so a test can wire up a topic, subscribe a queue, publish, and assert on delivery without touching a real cloud account.

| Provider | Real service | cloudemu driver |
|---|---|---|
| **AWS** | SNS — topics, subscriptions, and SNS → SQS fan-out | `aws.SNS` |
| **Azure** | Notification Hubs | `azure.NotificationHubs` |
| **GCP** | Firebase Cloud Messaging (FCM) | `gcp.FCM` |

There are two ways to drive it, both backed by the same in-memory state:

- **Real cloud SDK** — point your existing `aws-sdk-go-v2/service/sns`, `armnotificationhubs`, or FCM (`google.golang.org/api/fcm/v1`) client at a local server. Only the endpoint changes; your production code is untouched. This is the closest thing to testing against the real cloud, and what most tests should use.
- **Portable Go API** — call cloudemu's Go interface directly and skip the HTTP hop. The same method shape works across every cloud, so you can switch providers by changing one field.

## Drive it with the real SDK

cloudemu ships an HTTP server per cloud that speaks that provider's real wire protocol. You start it with `httptest`, hand it the drivers you need, and point your normal SDK client at its URL — nothing else in your code changes.

<Tabs items={['AWS', 'Azure', 'GCP']}>

<Tab value="AWS">

```go
import (
    "github.com/aws/aws-sdk-go-v2/aws"
    awssns "github.com/aws/aws-sdk-go-v2/service/sns"
    snstypes "github.com/aws/aws-sdk-go-v2/service/sns/types"
    awsserver "github.com/stackshy/cloudemu/server/aws"
)

cloud := cloudemu.NewAWS()
ts := httptest.NewServer(awsserver.New(awsserver.Drivers{SNS: cloud.SNS}))

client := awssns.NewFromConfig(cfg, func(o *awssns.Options) {
    o.BaseEndpoint = aws.String(ts.URL) // the only change from real AWS
})

topic, _ := client.CreateTopic(ctx, &awssns.CreateTopicInput{
    Name: aws.String("order-events"),
    Tags: []snstypes.Tag{{Key: aws.String("env"), Value: aws.String("test")}},
})
client.Subscribe(ctx, &awssns.SubscribeInput{
    TopicArn: topic.TopicArn,
    Protocol: aws.String("email"),
    Endpoint: aws.String("ops@example.com"),
})
```

## What each provider supports

All three providers implement the same notification interface, so the operations are identical — cloudemu just maps them onto each cloud's own vocabulary.

<Tabs items={['AWS', 'Azure', 'GCP']}>

<Tab value="AWS">

**SNS topics** — full CRUD via `CreateTopic`, `UpdateTopic` (display name and tags), `GetTopic`, `ListTopics`, and `DeleteTopic`.

**Subscriptions** — `Subscribe`, `Unsubscribe`, and `ListSubscriptions`, with the standard SNS protocols: `email`, `sms`, `http`, `https`, `sqs`, and `lambda`.

**Publishing** — `Publish` carries a subject, a message body, and arbitrary message attributes, and fans the message out to every subscriber on the topic.

</Tab>

<Tab value="Azure">

**Topics** — full CRUD via `CreateTopic`, `UpdateTopic`, `GetTopic`, `ListTopics`, and `DeleteTopic`. `UpdateTopic` mirrors ARM's `CreateOrUpdate` on an existing resource, replacing the display name and tags. Topics are scoped to a subscription and resource group.

**Subscriptions** — `Subscribe`, `Unsubscribe`, and `ListSubscriptions` register and enumerate the endpoints attached to a topic.

**Publishing** — `Publish` sends a message with a subject, body, and attributes to the topic's subscribers.

</Tab>

<Tab value="GCP">

**Topics** — full CRUD via `CreateTopic`, `UpdateTopic`, `GetTopic`, `ListTopics`, and `DeleteTopic`. Topics are scoped to a project.

**Subscriptions** — `Subscribe`, `Unsubscribe`, and `ListSubscriptions` manage the endpoints subscribed to a topic.

**Publishing** — `Publish` delivers a message, with a subject, body, and attributes, to every subscriber.

</Tab>

</Tabs>

## How the emulator behaves

cloudemu doesn't just store topics — it reproduces the side effects of publishing, so your tests exercise realistic delivery instead of a dumb key-value store:

- **Publishing fans out to SQS.** When the SNS backend is wired to the SQS backend, publishing to a topic delivers the SNS envelope JSON into every `sqs`-protocol subscription's queue — so a test can publish and then poll the queue, exactly like real SNS → SQS.
- **Topics track their subscribers.** Each topic's `SubscriptionCount` reflects the subscriptions currently attached, and `ListSubscriptions` returns them with their protocol, endpoint, and confirmation status.
- **Listing respects scope.** `ListTopics` filters by scope, so Azure subscription / resource-group and GCP project boundaries behave the way they do on the real API.

## Or call the Portable Go API directly

Call cloudemu's Go interface directly, in-process. The method shape is identical across clouds, so switching providers is a one-line change to the driver field.

<Tabs items={['AWS', 'Azure', 'GCP']}>

<Tab value="AWS">

```go
import notifdriver "github.com/stackshy/cloudemu/notification/driver"

topic, _ := aws.SNS.CreateTopic(ctx, notifdriver.TopicConfig{
    Name: "order-events",
})
aws.SNS.Subscribe(ctx, notifdriver.SubscriptionConfig{
    TopicID: topic.ID, Protocol: "email", Endpoint: "team@example.com",
})
aws.SNS.Publish(ctx, notifdriver.PublishInput{
    TopicID: topic.ID, Message: "New order received",
    Attributes: map[string]string{"orderType": "express"},
})
```
